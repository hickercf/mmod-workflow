# 知识库检索（kb-retrieval）

检索顺序**固定**，先外部后内部，绝对禁止整目录灌入上下文。规则与 `docs/workflow-design.md` 第 5 节、`AGENTS.md` / 内部 `INDEX.md` 的检索纪律一致。

## 1. 检索顺序

1. **外部索引**：先读
   `D:\数学建模知识库\MathModel-Agent-KB\00_Index\MOC-总索引.md`
   （能力卡 + 案例 + 策略的总索引，共 114 张卡）。
2. **外部决策规则**：读外部 `模型选择决策规则.md`。
3. **内部索引**：读内部 `knowledge-base/INDEX.md`（代码模板 + 蒸馏产物 + 本地索引）。
4. **按需单张读卡**：根据决策需要读相关卡片/模板，单张取用。

## 2. 回退规则

- **外部库缺失或校验失败时，仅回退内部库**，不编造卡片内容。
- 回退同样按"内部 INDEX → 按需单张读卡"进行，禁止整库读入。
- 外部库存在性/链接完整性校验入口：
  ```powershell
  $env:PYTHONIOENCODING='utf-8'
  python "D:\数学建模知识库\scripts\validate_links.py"
  ```

## 3. 使用纪律

- **按需**：只读解决当前决策需要的卡片；无关卡片不读。
- **单张**：每次 read 一张卡，不批量 read 目录。
- **模板复制后改**：从知识库取到的代码模板，solver 复制到 workspace 后再修改，不把模板细节灌进主上下文。
- **登记录用**：检索结果必须在产出中登记"读了哪几张卡、用于哪个决策"，落在：
  - S2 的 `MODELING_REPORT.md` / `model-selection.md`（模型选择依据 + 卡引用）；
  - 或对应步骤的产出文件（如 S1 分析、S3 求解的引用卡）。

## 4. 基准与启发边界

- 外部卡片/优秀论文只提供**方法与写法启发**（能力、案例、策略），不能把其数值、阈值、图表或结论写入本题工件。
- 参考论文只提供证据形态启发，不把其数据/结论用于本题。
- 本题所有数值必须来自 workspace 内可执行脚本产物，缺数据就写缺口并请用户补充。

## 5. 常见坑位与修正

| 错误 | 改正 |
|---|---|
| 直接 read 整目录 | 只读索引，再单张按需 |
| 外部库缺失仍引用其卡 | 回退内部库并注明 |
| 用了卡里的阈值/结论当本题结果 | 卡只提供方法/写法启发，数值必须来自 workspace 脚本产物 |
| 用了卡但没登记 | 在 MODELING_REPORT/model-selection 中补登记 |
| 混淆内部/外部索引 | 严格按顺序：外部 MOC-总索引 → 外部决策规则 → 内部 INDEX |

## 6. 每步触发点

- **S1 审题**：读题型/数据相关的分析卡，登记于 `analysis.md` 或 `PROBLEM_ANALYSIS.md`。
- **S2 建模**：读模型选择决策规则 + 候选模型能力卡，登记于 `MODELING_REPORT.md`/`model-selection.md`。
- **S3/S4 求解与深化**：按需取代码模板复制到 workspace 后改，登记引用卡。
- **S6 写作**：按需取论文写法/证据形态卡，只能启发写法，不能搬数值/结论。

## 7. 登记格式建议

在外卡使用处写一行留痕，例如：

```markdown
- 参考卡：`<卡名>`（外部/内部），用于 `<决策>`（候选筛选 / 主指标选取 / 数据清洗规则 / 写作结构）。
```

这样可被追溯，也满足"检索结果必须在产出中登记"的门禁要求。

## 8. 检索失败的处置

- 外部库无法访问 → 回退内部，注明"外部库缺失，回退内部 `knowledge-base/INDEX.md`"。
- 内部也缺所需卡 → 按需用其他来源（如教材/文献），但**不编造卡片存在**；在登记中如实说明替代依据。

## 9. 登记示例（S2 建模时）

`MODELING_REPORT.md` 或 `model-selection.md` 结尾可含一张简短登记表：

| 读取卡（外部/内部） | 用于决策 | 结论 |
|---|---|---|
| 外部 `插值与拟合.md` | 候选初筛 | 选用 spline baseline + 正则化 advanced |
| 外部 `模型选择决策规则.md` | 主指标选取 | 以 RMSE 为主指标，方向越小越优 |
| 内部 `代码模板/interp_fit.py` | 求解模板 | 复制到 workspace 后改 |

## 10. Token 纪律要点

- 只读所需卡，不整库灌入上下文；一次 read 一张卡。
- 主循环只读 summary/ledger 级别；代码细节留给 solver 与复现记录。
- 外部索引、决策规则、内部 INDEX 各读一次即够，不必重复重读。
